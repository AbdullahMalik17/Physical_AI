## Introduction

Simulation is the cornerstone of modern robotics development. Before deploying expensive hardware in real-world scenarios, we test, validate, and refine our algorithms in virtual environments. **Gazebo** is the industry-standard robot simulation platform, offering high-fidelity physics simulation, realistic sensor models, and seamless ROS 2 integration.

In this chapter, you'll learn to build complete simulated robot systems, from defining robot models to simulating complex environments with multiple sensors and actuators.

**Why Simulation Matters for Physical AI:**
- **Cost-effective**: Test dangerous scenarios without risking hardware
- **Reproducible**: Exact conditions every time, crucial for ML training
- **Rapid iteration**: No hardware setup delays
- **Parallel testing**: Run hundreds of scenarios simultaneously
- **Data generation**: Synthetic data for training perception models

## Gazebo Architecture Overview

Gazebo consists of several key components:

1. **Physics Engine** - Simulates dynamics (ODE, Bullet, DART, Simbody)
2. **Rendering Engine** - Visualizes the world (OGRE 1.x/2.x)
3. **Sensor Simulation** - Cameras, LiDAR, IMU, GPS, contact sensors
4. **Plugin System** - Extend functionality with custom behaviors
5. **World File (SDF)** - Defines environments, models, and physics
6. **Model Library** - Reusable robot and object models

### Gazebo vs. Gazebo Classic

As of 2022, Gazebo underwent a major rewrite:

| Feature | Gazebo Classic (11) | Gazebo (Ignition) |
|---------|---------------------|-------------------|
| **Status** | Maintenance mode | Active development |
| **Physics** | ODE primary | Multiple engines |
| **Performance** | Good | Excellent (multithreading) |
| **ROS 2 Integration** | ros_gz_bridge | Native support |
| **Rendering** | OGRE 1.x | OGRE 2.x (PBR) |
| **Recommended** | Legacy projects | New projects |

**For Physical AI**: We'll use **Gazebo Fortress/Garden** (modern Gazebo) with ROS 2 Humble.

## Setting Up Gazebo with ROS 2

### Installation

**Example 1: Install Gazebo Fortress with ROS 2**

```bash
# Update package list
sudo apt update

# Install Gazebo Fortress (recommended for ROS 2 Humble)
sudo apt install ros-humble-gazebo-ros-pkgs

# Install Gazebo development files
sudo apt install ros-humble-gazebo-dev

# Verify installation
gazebo --version
# Expected: Gazebo multi-robot simulator, version 11.10.2

# Test Gazebo launch
ros2 launch gazebo_ros gazebo.launch.py

# You should see an empty Gazebo world with ground plane
```

### First Simulation: Empty World

**Example 2: Launch Gazebo with ROS 2**

```python
# save as: gazebo_empty_world.launch.py
from launch import LaunchDescription
from launch_ros.actions import Node
from launch.actions import IncludeLaunchDescription
from launch.launch_description_sources import PythonLaunchDescriptionSource
from ament_index_python.packages import get_package_share_directory
import os


def generate_launch_description():
    gazebo_ros_dir = get_package_share_directory('gazebo_ros')

    gazebo = IncludeLaunchDescription(
        PythonLaunchDescriptionSource(
            os.path.join(gazebo_ros_dir, 'launch', 'gazebo.launch.py')
        ),
        launch_arguments={
            'world': '',  # Empty world
            'verbose': 'true',
            'pause': 'false',
        }.items()
    )

    return LaunchDescription([
        gazebo,
    ])
```

**Launch it:**
```bash
ros2 launch your_package gazebo_empty_world.launch.py
```

## Robot Description with URDF

**URDF (Unified Robot Description Format)** is XML-based format for defining robot kinematic and dynamic properties.

### URDF Structure

A URDF file consists of:
- **Links**: Rigid bodies (chassis, wheels, sensors)
- **Joints**: Connections between links (revolute, continuous, fixed, prismatic)
- **Visuals**: Appearance (meshes, colors)
- **Collisions**: Simplified geometry for physics
- **Inertials**: Mass, center of mass, inertia matrix

**Example 3: Simple Differential Drive Robot URDF**

```xml
<?xml version="1.0"?>
<robot name="simple_robot">
  <!-- Base Link -->
  <link name="base_link">
    <visual>
      <geometry>
        <box size="0.6 0.4 0.2"/>
      </geometry>
      <material name="blue">
        <color rgba="0.0 0.0 0.8 1.0"/>
      </material>
    </visual>
    <collision>
      <geometry>
        <box size="0.6 0.4 0.2"/>
      </geometry>
    </collision>
    <inertial>
      <mass value="15.0"/>
      <inertia ixx="0.13" ixy="0.0" ixz="0.0"
               iyy="0.21" iyz="0.0" izz="0.13"/>
    </inertial>
  </link>

  <!-- Left Wheel -->
  <link name="left_wheel">
    <visual>
      <geometry>
        <cylinder radius="0.1" length="0.05"/>
      </geometry>
      <material name="black">
        <color rgba="0.0 0.0 0.0 1.0"/>
      </material>
    </visual>
    <collision>
      <geometry>
        <cylinder radius="0.1" length="0.05"/>
      </geometry>
    </collision>
    <inertial>
      <mass value="0.5"/>
      <inertia ixx="0.001" ixy="0.0" ixz="0.0"
               iyy="0.001" iyz="0.0" izz="0.001"/>
    </inertial>
  </link>

  <!-- Joint: Base to Left Wheel -->
  <joint name="base_to_left_wheel" type="continuous">
    <parent link="base_link"/>
    <child link="left_wheel"/>
    <origin xyz="0.0 0.225 -0.05" rpy="1.5708 0 0"/>
    <axis xyz="0 0 1"/>
  </joint>

  <!-- Right Wheel (similar structure) -->
  <link name="right_wheel">
    <visual>
      <geometry>
        <cylinder radius="0.1" length="0.05"/>
      </geometry>
      <material name="black">
        <color rgba="0.0 0.0 0.0 1.0"/>
      </material>
    </visual>
    <collision>
      <geometry>
        <cylinder radius="0.1" length="0.05"/>
      </geometry>
    </collision>
    <inertial>
      <mass value="0.5"/>
      <inertia ixx="0.001" ixy="0.0" ixz="0.0"
               iyy="0.001" iyz="0.0" izz="0.001"/>
    </inertial>
  </link>

  <joint name="base_to_right_wheel" type="continuous">
    <parent link="base_link"/>
    <child link="right_wheel"/>
    <origin xyz="0.0 -0.225 -0.05" rpy="1.5708 0 0"/>
    <axis xyz="0 0 1"/>
  </joint>

  <!-- Caster Wheel (for stability) -->
  <link name="caster_wheel">
    <visual>
      <geometry>
        <sphere radius="0.05"/>
      </geometry>
      <material name="gray">
        <color rgba="0.5 0.5 0.5 1.0"/>
      </material>
    </visual>
    <collision>
      <geometry>
        <sphere radius="0.05"/>
      </geometry>
    </collision>
    <inertial>
      <mass value="0.1"/>
      <inertia ixx="0.0001" ixy="0.0" ixz="0.0"
               iyy="0.0001" iyz="0.0" izz="0.0001"/>
    </inertial>
  </link>

  <joint name="base_to_caster" type="fixed">
    <parent link="base_link"/>
    <child link="caster_wheel"/>
    <origin xyz="-0.25 0.0 -0.15" rpy="0 0 0"/>
  </joint>
</robot>
```

**Key URDF Concepts:**
- **Origin**: Position (xyz) and orientation (rpy = roll, pitch, yaw)
- **Axis**: Rotation/translation direction for joints
- **Inertia**: Must be positive-definite for physics stability
- **Continuous joints**: Infinite rotation (wheels)
- **Fixed joints**: Rigid connection (sensors, casters)

## SDF Format: Gazebo's Native Language

**SDF (Simulation Description Format)** is more powerful than URDF, supporting:
- Multiple robots in one file
- Lights, cameras, and sensors
- Physics engine parameters
- Plugin configurations
- Nested models

**Example 4: SDF World File with Robot**

```xml
<?xml version="1.0"?>
<sdf version="1.8">
  <world name="robot_world">
    <!-- Physics Engine Configuration -->
    <physics name="1ms" type="ode">
      <max_step_size>0.001</max_step_size>
      <real_time_factor>1.0</real_time_factor>
      <real_time_update_rate>1000</real_time_update_rate>
    </physics>

    <!-- Lighting -->
    <light name="sun" type="directional">
      <cast_shadows>true</cast_shadows>
      <pose>0 0 10 0 0 0</pose>
      <diffuse>0.8 0.8 0.8 1</diffuse>
      <specular>0.2 0.2 0.2 1</specular>
      <direction>-0.5 0.1 -0.9</direction>
    </light>

    <!-- Ground Plane -->
    <model name="ground_plane">
      <static>true</static>
      <link name="link">
        <collision name="collision">
          <geometry>
            <plane>
              <normal>0 0 1</normal>
            </plane>
          </geometry>
        </collision>
        <visual name="visual">
          <geometry>
            <plane>
              <normal>0 0 1</normal>
              <size>100 100</size>
            </plane>
          </geometry>
          <material>
            <ambient>0.8 0.8 0.8 1</ambient>
            <diffuse>0.8 0.8 0.8 1</diffuse>
          </material>
        </visual>
      </link>
    </model>

    <!-- Include Robot Model -->
    <include>
      <uri>model://simple_robot</uri>
      <pose>0 0 0.5 0 0 0</pose>
    </include>

    <!-- Obstacle: Wall -->
    <model name="wall">
      <static>true</static>
      <pose>5 0 1 0 0 0</pose>
      <link name="link">
        <collision name="collision">
          <geometry>
            <box>
              <size>0.2 10 2</size>
            </box>
          </geometry>
        </collision>
        <visual name="visual">
          <geometry>
            <box>
              <size>0.2 10 2</size>
            </box>
          </geometry>
          <material>
            <ambient>0.7 0.1 0.1 1</ambient>
            <diffuse>0.7 0.1 0.1 1</diffuse>
          </material>
        </visual>
      </link>
    </model>
  </world>
</sdf>
```

## Sensor Simulation

Gazebo simulates a wide range of sensors critical for robotics.

### Camera Sensor

**Example 5: RGB Camera Sensor in URDF with Gazebo Plugin**

```xml
<!-- Camera Link -->
<link name="camera_link">
  <visual>
    <geometry>
      <box size="0.05 0.05 0.05"/>
    </geometry>
    <material name="red">
      <color rgba="1.0 0.0 0.0 1.0"/>
    </material>
  </visual>
  <collision>
    <geometry>
      <box size="0.05 0.05 0.05"/>
    </geometry>
  </collision>
  <inertial>
    <mass value="0.1"/>
    <inertia ixx="0.0001" ixy="0.0" ixz="0.0"
             iyy="0.0001" iyz="0.0" izz="0.0001"/>
  </inertial>
</link>

<joint name="camera_joint" type="fixed">
  <parent link="base_link"/>
  <child link="camera_link"/>
  <origin xyz="0.3 0 0.15" rpy="0 0 0"/>
</joint>

<!-- Gazebo Plugin for Camera -->
<gazebo reference="camera_link">
  <sensor name="camera" type="camera">
    <update_rate>30</update_rate>
    <camera>
      <horizontal_fov>1.047</horizontal_fov>
      <image>
        <width>640</width>
        <height>480</height>
        <format>R8G8B8</format>
      </image>
      <clip>
        <near>0.1</near>
        <far>100</far>
      </clip>
    </camera>
    <plugin name="camera_controller" filename="libgazebo_ros_camera.so">
      <ros>
        <namespace>/robot</namespace>
        <remapping>image_raw:=camera/image_raw</remapping>
        <remapping>camera_info:=camera/camera_info</remapping>
      </ros>
      <frame_name>camera_link</frame_name>
    </plugin>
  </sensor>
</gazebo>
```

**Accessing camera data in ROS 2:**
```bash
ros2 topic echo /robot/camera/image_raw
ros2 run image_view image_view --ros-args --remap image:=/robot/camera/image_raw
```

## Differential Drive Plugin

To make the robot move, we need a controller plugin.

**Example 8: Differential Drive Controller**

```xml
<!-- Add to your URDF, inside <robot> tag -->
<gazebo>
  <plugin name="diff_drive" filename="libgazebo_ros_diff_drive.so">
    <ros>
      <namespace>/robot</namespace>
    </ros>

    <!-- Wheel joints -->
    <left_joint>base_to_left_wheel</left_joint>
    <right_joint>base_to_right_wheel</right_joint>

    <!-- Kinematics -->
    <wheel_separation>0.45</wheel_separation>
    <wheel_diameter>0.2</wheel_diameter>

    <!-- Limits -->
    <max_wheel_torque>20</max_wheel_torque>
    <max_wheel_acceleration>1.0</max_wheel_acceleration>

    <!-- Output -->
    <publish_odom>true</publish_odom>
    <publish_odom_tf>true</publish_odom_tf>
    <publish_wheel_tf>true</publish_wheel_tf>

    <odometry_frame>odom</odometry_frame>
    <robot_base_frame>base_link</robot_base_frame>

    <!-- Topic names -->
    <command_topic>cmd_vel</command_topic>
    <odometry_topic>odom</odometry_topic>
  </plugin>
</gazebo>
```

**Control the robot with keyboard:**

## Spawning Robots in Gazebo

**Example 9: Spawn Robot from URDF File**

```python
# spawn_robot.launch.py
from launch import LaunchDescription
from launch_ros.actions import Node
from launch.actions import IncludeLaunchDescription, ExecuteProcess
from launch.launch_description_sources import PythonLaunchDescriptionSource
from ament_index_python.packages import get_package_share_directory
import os


def generate_launch_description():
    pkg_dir = get_package_share_directory('your_robot_package')
    urdf_file = os.path.join(pkg_dir, 'urdf', 'robot.urdf')

    # Read URDF file
    with open(urdf_file, 'r') as file:
        robot_desc = file.read()

    # Launch Gazebo
    gazebo = IncludeLaunchDescription(
        PythonLaunchDescriptionSource(
            os.path.join(get_package_share_directory('gazebo_ros'),
                        'launch', 'gazebo.launch.py')
        )
    )

    # Spawn robot
    spawn_robot = Node(
        package='gazebo_ros',
        executable='spawn_entity.py',
        arguments=[
            '-entity', 'my_robot',
            '-topic', 'robot_description',
            '-x', '0.0',
            '-y', '0.0',
            '-z', '0.5'
        ],
        output='screen'
    )

    # Robot state publisher
    robot_state_publisher = Node(
        package='robot_state_publisher',
        executable='robot_state_publisher',
        parameters=[{'robot_description': robot_desc}]
    )

    return LaunchDescription([
        gazebo,
        robot_state_publisher,
        spawn_robot
    ])
```

## Physics Engine Tuning

Proper physics configuration is crucial for simulation accuracy.

**Key Physics Parameters:**
- **max_step_size**: Smaller = more accurate, slower (default: 0.001s)
- **real_time_factor**: Target speed ratio (1.0 = real-time)
- **solver iterations**: More = stable but slower (default: 50)

**Tips for Stable Simulation:**
1. **Inertia matrices must be positive-definite**
2. **Collision geometries should be simpler than visuals**
3. **Avoid very small or very large masses** (keep within 0.01-1000 kg)
4. **Use appropriate contact parameters** (friction, damping)

## Best Practices

### 1. Model Organization
```
robot_package/
├── urdf/
│   ├── robot.urdf
│   ├── robot.gazebo  # Gazebo-specific tags
│   └── materials.xacro
├── meshes/
│   ├── chassis.dae
│   └── wheel.stl
├── worlds/
│   └── test_world.sdf
└── launch/
    └── gazebo.launch.py
```

### 2. Use Xacro for Modularity

URDF files get verbose. Use **xacro** (XML macros):

```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro" name="robot">
  <xacro:property name="wheel_radius" value="0.1"/>
  <xacro:property name="wheel_width" value="0.05"/>

  <xacro:macro name="wheel" params="prefix xyz">
    <link name="${prefix}_wheel">
      <visual>
        <geometry>
          <cylinder radius="${wheel_radius}" length="${wheel_width}"/>
        </geometry>
      </visual>
    </link>
    <joint name="base_to_${prefix}_wheel" type="continuous">
      <parent link="base_link"/>
      <child link="${prefix}_wheel"/>
      <origin xyz="${xyz}" rpy="1.5708 0 0"/>
    </joint>
  </xacro:macro>

  <xacro:wheel prefix="left" xyz="0 0.225 -0.05"/>
  <xacro:wheel prefix="right" xyz="0 -0.225 -0.05"/>
</robot>
```

Convert to URDF:
```bash
xacro robot.xacro > robot.urdf
```

